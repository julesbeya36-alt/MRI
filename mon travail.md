# Mon travail

## 1) Ce que j’ai déjà préparé
- Le serveur Node.js est prêt pour servir les pages HTML.
- La base SQLite est configurée automatiquement au démarrage.
- L’API pour les actualités et les messages de contact est en place.
- L’admin simple avec mot de passe local est prêt.
- Le projet est compatible avec Render via le fichier render.yaml.

## 2) Ce qui reste à faire pour finir le site
### A. Contenu réel du site
- Remplacer les textes de démonstration par les vrais contenus de l’église.
- Ajouter les vraies photos, logo et visuels.
- Vérifier les horaires, coordonnées, adresse et réseaux sociaux.

### B. Configuration de production
- Choisir le bon hébergement (Render, Vercel, Netlify, etc.).
- Ajouter la vraie variable DATABASE_URL si tu utilises PostgreSQL/Supabase.
- Vérifier le port et les variables d’environnement du serveur.

### C. Sécurité et accès admin
- Changer le mot de passe admin dans le fichier script.js.
- Ne pas laisser le mot de passe par défaut dans le code final.
- Prévoir une vraie authentification si le site est mis en ligne.

### D. Formulaire de contact
- Brancher le formulaire sur un vrai système de messagerie ou un service de réception.
- Ajouter un email réel ou un stockage de messages sécurisé.
- Vérifier que les messages arrivent bien dans la boîte de réception.

### E. Validation du site
- Tester chaque page dans le navigateur.
- Vérifier que les liens, images et boutons fonctionnent.
- Vérifier l’affichage mobile et les erreurs Console/Network.

## 3) Ce que je ne peux pas faire pour toi manuellement
Je ne peux pas faire à ta place :
- Choisir le nom exact de ton site, le branding et les couleurs.
- Écrire le contenu officiel de l’église ou des publications.
- Ajouter tes vraies coordonnées, adresse, téléphone et email.
- Créer/obtenir un compte Render, Supabase, domaine ou hébergement.
- Définir ton mot de passe final, tes identifiants et les accès réels.
- Publier le site en ligne avec un vrai nom de domaine.
- Valider les éléments légaux, conformité, ou acceptation du client.
- Déclarer les permissions et accès réels de ton organisation.

## 4) Ce que tu dois faire toi-même
1. Renseigne le vrai contenu du site.
2. Mets les vraies images/vidéos/logo.
3. Change le mot de passe admin dans le code.
4. Choisis l’hébergement et la base de données réelles.
5. Vérifie le site en local puis en ligne.
6. Configure l’envoi réel des messages de contact.
7. Publie le site final avec le bon domaine.

## 5) Prochaine étape recommandée
- on commence par : remplacer les contenus factices par les vrais contenus de ton église,
- puis on configure l’hébergement réel,
- puis on sécurise l’admin et le formulaire.
